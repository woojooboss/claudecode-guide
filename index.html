01 · 무엇에 관한 영상인가

Claude를 만든 회사가
“진짜 사용법”을 풀었다.

Claude Code는 Anthropic이 만든 AI 코딩 도구입니다. 이 영상의 제작자 Boris는 그 도구를 직접 설계한 사람입니다.

한 줄 요약

그동안의 AI 코딩 도구가 “한두 줄을 추천”하는 수준이었다면, Claude Code는 기능 전체를 짜고, 파일 전체를 만들고, 버그를 한 번에 고치는 단계로 넘어갔습니다.

Boris의 메시지는 일관됩니다. “우리가 시킨 게 아니라, 모델이 똑똑해서 알아서 한다.” 그러니까 우리가 할 일은 화려한 명령어를 외우는 게 아니라, 모델이 똑똑하게 굴 수 있는 환경을 만들어 주는 것입니다.

이 문서는 그 환경을 만드는 다섯 가지 원칙을 정리한 것입니다.

잠깐, 용어 정리.
이 문서에는 개발자들이 쓰는 단어가 몇 번 등장합니다. 어렵게 느껴지면 아래만 기억하셔도 됩니다.
· 코드 = 프로그램을 움직이는 글
· 코드베이스 = 코드가 모여있는 작업 폴더 전체
· 터미널 = 컴퓨터에 직접 명령어를 입력하는 검은 창
· CLI = 그 검은 창에서 쓰는 명령어 프로그램
· git = 코드의 변경 이력을 자동 기록하는 도구
02 · 핵심 5원칙

설정 한두 가지만 바꿔도
결과 품질이 달라진다.

Boris가 27분 동안 반복해서 강조한 다섯 가지입니다. 이 다섯 개만 알면 Claude Code를 두 배, 세 배 더 똑똑하게 쓸 수 있습니다.

(01)
PRINCIPLE 01

처음부터 시키지 말고,
먼저 “물어보라.”

새 직원이 회사에 오면 첫날부터 일을 시키지 않습니다. 회사 구조부터 설명합니다. Claude Code도 똑같습니다.

가장 흔한 실수는 첫 화면에서 곧바로 “이런 기능 만들어줘” 라고 명령하는 것입니다. 그 대신 Anthropic이 신입에게 시키는 일은 단 하나입니다. “이 폴더에 대해 질문하기.”

“이 코드는 어디에서 어떻게 쓰여?” “이 함수는 왜 인자가 15개나 돼?” “이 기능은 누가 언제 만들었어?” 이런 질문부터 던져서 작업 폴더의 구조를 머릿속에 그린 다음에 작업을 시작합니다.

이 방법으로 Anthropic의 신규 엔지니어 적응 기간이 2~3주에서 2~3일로 줄었습니다.
왜 안전한가? Claude Code는 코드를 외부 서버로 보내지 않습니다. 내 컴퓨터 안에서만 작동하고, 학습에도 사용되지 않습니다. 사내 코드도 안심하고 질문할 수 있습니다.
(02)
PRINCIPLE 02

바로 쓰게 하지 말고
“계획부터” 세우게 하라.

“3만 줄짜리 결제 기능을 만들어줘”라고 한 번에 부탁하면 열에 아홉은 엉뚱한 결과가 나옵니다. AI가 멍청해서가 아니라, 사람도 그런 식으로 일하지 않기 때문입니다.

해결책은 별 거 없습니다. 부탁하기 전에 문장 하나만 덧붙이면 됩니다.

“코드를 쓰기 전에, 먼저 아이디어를 정리하고 계획을 세운 뒤,
나와 함께 검토하고 승인을 받은 다음에 작성해줘.”

이 한 문장이면 끝입니다. 별도의 설정도, 도구도 필요 없습니다. 결과 품질이 눈에 띄게 올라갑니다.

(03)
PRINCIPLE 03

내가 쓰는 도구를
연결해 두어라.

평소에 자주 쓰는 명령어와 외부 도구가 있다면, Claude Code에게 한 번만 알려주세요. 그 이후로는 알아서 꺼내 씁니다.

연결할 수 있는 도구는 두 종류입니다.

  • 내 컴퓨터의 명령어 — 평소 터미널에서 자주 쓰는 명령어를 알려주면 그대로 사용합니다.
  • 외부 도구 연결(MCP) — 슬랙, 노션, 디자인 툴 등 외부 서비스와 연결하는 표준 규격입니다. 추가하고 사용법만 알려주면 즉시 활용합니다.
요점은 한 가지. Claude Code는 연결된 만큼 일합니다.
MCP란? Model Context Protocol의 약자로, AI와 외부 도구를 연결하는 표준 규격입니다. 쉽게 말해 “Claude가 다른 프로그램에 손을 뻗을 수 있게 해주는 통로”입니다.
(04)
PRINCIPLE 04

“스스로 확인할 수단”을
쥐여주면 거의 완벽해진다.

Boris가 워크샵에서 가장 강하게 강조한 부분입니다. Claude Code에게 자기 결과를 검증할 수단을 주면 결과가 차원이 달라집니다.

예를 들어 웹 화면을 만들어달라고 부탁할 때, 그냥 “만들어줘”라고만 하면 한 번에 만족스러운 결과가 나오기 어렵습니다. 그런데 “만든 다음에 스크린샷을 찍어서 직접 확인하고, 어색하면 다시 고쳐”라고 하면 두세 번 스스로 반복하면서 거의 완벽한 결과를 가져옵니다.

코딩이라면 자동 테스트, 디자인이라면 스크린샷, 앱이라면 시뮬레이터. 피드백 수단을 줘라. 이게 핵심입니다.

사람이 일일이 점검하지 않아도, AI가 스스로 점검·수정·재시도합니다.
(05)
PRINCIPLE 05

한 번 설정하고
“팀과 공유”하라.

작업 폴더 안에 CLAUDE.md 라는 메모 파일을 하나 만들어 두면, Claude Code가 매번 자동으로 읽습니다.

여기에는 이런 걸 적어두면 좋습니다.

  • 이 프로젝트에서 자주 쓰는 명령어
  • “이런 식으로 작성해줘” 같은 작업 규칙
  • 주의해야 할 파일·폴더
  • 같이 일하는 동료가 알아야 할 맥락

핵심은 다음입니다. 이 파일을 팀과 공유하는 순간, 한 사람의 설정이 조직 전체의 자산이 됩니다. 누군가 한 번 잘 만들어두면 모두가 그 혜택을 봅니다.

Anthropic의 기술 인력 약 80%가 매일 Claude Code를 사용하는 이유 중 하나입니다.
CLAUDE.md란? 작업 폴더에 두는 텍스트 메모 파일입니다. 매 작업이 시작될 때 자동으로 읽혀, 별도로 명령하지 않아도 그 안의 내용이 기본 설정처럼 적용됩니다. 너무 길면 오히려 방해되니 짧게 유지하세요.

“우리가 일일이 시킨 게 아닙니다.
모델이 똑똑해서 알아서 합니다.”

— Boris, Claude Code 제작자

03 · 알아두면 좋은 단축키

27분 영상에서
가장 자주 나온 네 가지.

이 네 개만 알아도 사용 경험이 확연히 달라집니다.

Shift + Tab
자동 승인 모드
파일 수정마다 일일이 확인하지 않아도 알아서 진행하게 합니다. 방향이 맞을 때나 반복 작업에 유용합니다.
#
기억시키기
“이건 기억해 둬”라고 가르치는 키. 잘못된 사용법을 고쳐주거나 새 규칙을 추가할 때 사용합니다.
!
컴퓨터 명령 직접 실행
컴퓨터에 직접 명령어를 내리고, 그 결과를 Claude가 이어받아 작업합니다. 긴 명령을 빠르게 처리할 때.
Esc
즉시 중단
하던 일을 안전하게 멈춥니다. 방향이 어긋났다 싶으면 망설이지 말고 중단 → 다시 지시.
@파일명
파일 콕 집어 알려주기
특정 파일이나 폴더를 작업 맥락에 추가합니다. “이 파일 참고해서 작업해줘” 할 때 사용.
Esc Esc
이전 상태로 되돌리기
Esc를 두 번 누르면 이전 대화 지점으로 돌아갑니다. 잘못 지시했을 때 복구 수단.
04 · 한 단계 더

익숙해진 다음에
알면 좋은 것들.

처음부터 알 필요는 없지만, 손에 익은 뒤 한 단계 더 나아가고 싶을 때 참고하세요.

📁 설정 계층 — 개인 / 팀 / 회사

Claude Code의 설정은 세 단계로 나뉩니다. 프로젝트별 설정(폴더마다 따로), 개인 전역 설정(내 컴퓨터 전체), 회사 정책(관리자가 배포하는 규칙). 한 사람이 잘 만들면 팀 전체가 같이 쓸 수 있는 구조입니다.

⚡ 자동화 (SDK / -p 옵션)

Claude Code는 대화창에서만 쓰는 게 아니라, 자동화 스크립트의 일부로도 쓸 수 있습니다. 예를 들어 “이번 주에 우리 팀이 무엇을 출시했는지 git 기록 보고 정리해줘” 같은 반복 작업을 자동화할 수 있습니다. Anthropic 사내에서도 이렇게 활용합니다.

🧩 병렬 실행 — “Claude 여러 명”

Boris 본인도 보통 Claude Code 창을 여러 개 띄워놓고 일합니다. 한 창에서는 기능을 만들고, 다른 창에서는 테스트를 돌리고, 또 다른 창에서는 문서를 정리하는 식입니다. 익숙해지면 “AI 동료들을 동시에 부리는” 감각이 됩니다.

🖼️ 이미지·스크린샷도 자유롭게

처음부터 이미지 인식이 지원됩니다. 화면을 캡처해서 끌어다 놓거나 붙여넣으면 그대로 이해합니다. “이 디자인 시안처럼 만들어줘” 같은 부탁이 가능합니다.

🗣️ 받아쓰기로 더 빠르게

긴 지시 사항은 음성 입력이 훨씬 빠릅니다. 운영체제의 받아쓰기 기능을 켜고 동료에게 말하듯 부탁하세요. Boris도 실제로 그렇게 씁니다.

05 · 자주 묻는 질문

워크샵 Q&A 정리.

영상 후반부에 나온 질의응답을 그대로 옮긴 것입니다.

왜 IDE(코딩 전용 프로그램)가 아니라 터미널을 쓰나요?
두 가지 이유입니다. 첫째, 사람마다 쓰는 프로그램이 너무 다양합니다(VS Code, Xcode, Vim 등). 어떤 도구를 쓰든 공통으로 통하는 게 터미널이라 거기에 맞췄습니다. 둘째, AI 모델 자체가 워낙 빠르게 발전하기 때문에, 무거운 UI를 만들어 두면 모델이 발전할 때 같이 뜯어고쳐야 합니다. 가벼운 형태로 유지하는 게 합리적이었습니다.
가장 어려웠던 기술 문제는 무엇이었나요?
컴퓨터 명령어를 안전하게 실행시키는 부분이었습니다. 명령어 하나가 시스템 전체를 바꿀 수 있기 때문에, 매번 사용자에게 확인을 받자니 답답하고, 그냥 다 허용하자니 위험합니다. 결국 “읽기만 하는 명령은 자유롭게, 변경하는 명령은 신중하게”라는 단계별 권한 체계를 만들었습니다.
Anthropic 내부에서는 얼마나 쓰나요?
엔지니어, 연구원 모두가 매일 사용합니다. 기술직 인력의 약 80%가 매일 Claude Code를 씁니다. 코드를 직접 쓰지 않는 직무도 활용합니다. 예를 들어 연구원들은 노트북(데이터 분석용 도구) 작업에 쓰기도 합니다.
비개발자도 쓸 수 있나요?
쓸 수 있습니다. 다만 “코드를 쓰지 않는다”와 “파일·폴더 개념을 모른다”는 다릅니다. 기본적으로 작업 폴더가 무엇인지, 터미널 창을 어떻게 여는지 정도는 알아야 합니다. 그 이후로는 동료에게 부탁하듯 한국어로 쓰면 됩니다.
내 코드가 학습에 사용되나요?
아닙니다. Claude Code는 코드를 내 컴퓨터 안에서만 다룹니다. 외부 데이터베이스를 만들지도 않고, 학습에도 사용되지 않습니다. 이게 사내 코드에서도 안심하고 쓸 수 있는 이유입니다.
